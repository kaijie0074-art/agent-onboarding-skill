# 项目 03 · 关键信息自动推送到飞书（成果直送手机）

> 教练读完本文件后，照"带练步骤"一步步执行。一次只推进一步。

## 一句话目标
让 Agent 把整理好的信息（群日报/竞品动态/经营数据等）自动推送到你的飞书，手机随时看。这是个"放大器"——让其他项目的成果自动送到你手机上。

## 适合谁
所有想把成果随时在手机上看的人（创业者、大学生、自由职业者都适用）。

## ⚠️ 诚实关键点（开始前必须让用户知道）
这个项目**不是开箱即用、也不是"扫个码"就能用**。纯新手的 Agent 默认连不上飞书，必须先做一次性配置。给两条路，二选一：

- 🚀 **最快路线（零安装，约 5 分钟）· 飞书群机器人**：用户在飞书建个群 → 群设置 → 添加"自定义机器人" → 复制它的 webhook 网址 → 对 Agent 说"我有个飞书群机器人 webhook 是【网址】，以后我说推送你就用联网 POST 到这里"。之后日常说"推送到飞书"即可，全程不用装任何东西。缺点：只能发到群，不能私聊。
- 🛠 **完整路线（约 10–20 分钟）· 装飞书工具**：让 Agent 帮你装 `npm i -g @larksuite/cli` 并引导一次飞书登录授权。能力最全（私聊/建文档/发文件）。这步 Agent 一步步带，但要用户在浏览器/飞书里点几下，只做一次。

## 核心咒语（最终要教会用户说的那句话，已加防坑约束）
配置好后，日常只说这一句：**「把刚才整理的关键信息推送到我的飞书。」**

## 环境自检（开始前，教练静默判断）
- 能力需求：本机要有一条能到飞书的通道——要么有群机器人 webhook，要么装了飞书工具（lark-cli）。
- 检查：是否已记录过 webhook 网址，或本机是否已装 `lark-cli`（能力最全的飞书命令行工具）。
- 🔴 缺了怎么办：用 AskUserQuestion 让用户三选一——**最快路线（群机器人 webhook）/ 完整路线（装飞书工具）/ 暂时跳过**。这是个高门槛档位（🔴），别假装能一键搞定。
- 本机若已装好 lark-cli，那是"预装"状态，别把"已配好"当成所有新手的默认前提。

## 准备输入
- 要推送的内容：通常就是上一个项目刚做好的成果（比如项目 01 的群日报、竞品动态、经营数据汇总等）。
- 如果用户还没整理好内容，先回到对应项目把内容做出来，再来这一步。

## 带练步骤（一步一句，做完回报再走下一步）
1. 先判断有没有飞书通道：有 webhook 或 lark-cli → 直接进第 4 步；都没有 → 进第 2 步。
2. 没通道就引导配置（AskUserQuestion 三选一）：最快路线 / 完整路线 / 暂时跳过。让用户说"第几个"。
3. 按用户选择落地：最快路线 → 引导用户在飞书群里加自定义机器人、把 webhook 网址告诉 Agent；完整路线 → 帮装 `npm i -g @larksuite/cli`，**授权前先查代理（见防坑第 1 条）：有代理就用 `LARK_CLI_NO_PROXY=1 lark-cli auth login`**，再把生成的二维码/链接给用户扫，一步步带完一次授权。
4. 把要推送的内容整理成飞书消息格式（标题 + 重点摘要 + 必要时附原文/链接），别直接把一大坨原始文本丢过去。
5. 推送：webhook 走联网 POST 发到群；lark-cli 走飞书工具发私聊/群。
6. 确认送达，告诉用户：**去手机飞书查收。**

## 成功标准
用户的手机飞书真的收到了一条整理好的消息——不是一堆乱码或原始数据，而是有标题、有重点的可读消息。

## 防坑护栏（必须遵守）
- 🛑 **代理坑（中国用户高发，必查）**：很多人开着科学上网代理（Clash/V2Ray，常见 `127.0.0.1:7890` 或 `7897`）。**代理会破坏飞书的扫码/OAuth 授权流**，表现为扫码后报 **`flow_id 请求不合法 / 错误码 20001`** 或登录一直失败。
  - 处理：**凡是跑 `lark-cli` 的命令（尤其 `auth login` 授权、`drive +import`、推送），都加前缀 `LARK_CLI_NO_PROXY=1`**，例如 `LARK_CLI_NO_PROXY=1 lark-cli auth login`。或在该命令前临时清掉 `HTTP_PROXY/HTTPS_PROXY/ALL_PROXY`。
  - 自检：动手前先 `env | grep -i proxy` 看有没有代理；有就默认全程带 `LARK_CLI_NO_PROXY=1`，别等扫码失败才补救。
  - 若已经报了"请求不合法/20001"：**别让用户反复扫那个旧码**——旧授权流已废，必须关代理后**重新发起授权、生成新二维码/新链接**给用户，再扫新的。
- webhook 那串网址，必须用户自己在飞书群里加"自定义机器人"才能拿到，**Agent 代办不了那一步**——要诚实说明，别让用户以为 Agent 能凭空生成。
- 本机若已装好 lark-cli 是"预装"状态，别把"已配好"当成所有新手的默认前提；换台没装的电脑就得重新配。
- 整理成消息格式再发，别把原始长文本直接糊过去。

## 教学闭环（做完这样讲）
- "刚才你只说了：『推送到飞书』。"
- "Agent 自动完成了：把内容转成消息格式、发到你手机飞书。"
- "这件事原本要：导出 → 复制 → 转发，一串手工操作。"
- "以后你做任何项目，做完只要加一句：『推到我飞书』，成果就直接到手机。"
- "还能这样玩：① 推到某个指定的群；② 生成飞书在线文档、把链接发给你。"

## Claude Code vs Codex（同样一句话，不同 Agent 的差别）
- Claude Code 这边飞书工具生态成熟，配好后直接用。
- Codex 默认要自己接飞书 API，门槛更高。

## 进阶（问用户要不要）
- 配合定时任务，做成"每天早报自动推送"——每天早上自动把昨天的群日报/数据汇总推到你手机飞书。
