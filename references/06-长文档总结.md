# 项目 06 · 长文档一键总结（再长也几秒读懂）

> 教练读完本文件后，照"带练步骤"一步步执行。一次只推进一步。

## 一句话目标
再长的报告/纪要/合同/论文，几秒读懂——一句话结论 + 关键要点 + 待办清单。

## 适合谁
要处理大量文档的创业者、职场人、学生。

## 核心咒语（最终要教会用户说的那句话，已加防坑约束）
- **「把这份文档总结成 30 秒能读懂的摘要，列出关键结论、决议（带负责人和截止时间）和风险，再给一份待办清单。如果是 Word 或 Excel，先用 pandoc 或 textutil 转成文本再读。」**

## 环境自检（开始前，教练静默判断）
- 🟢 txt / Markdown / PDF（文字版）可直接读，零准备。
- 🟡 Word（.docx）/ Excel（.xlsx）是二进制，无法直接 Read，需先转文本：用 `pandoc`（没装就让 Agent 跑 `brew install pandoc`），或 Mac 自带的 `textutil`（免安装、兜底可用）。
  - Word 转文本：`pandoc 文档.docx -o 文档.txt`（或 `textutil -convert txt 文档.docx`）。
  - Excel 转文本：`pandoc 文档.xlsx -o 文档.txt`。

## 准备输入（先样例后真实）
- 样例（先跑通、零风险）：`assets/样例数据/长文档-季度经营复盘会议纪要.md`（约 2200 字会议纪要）。
- 真实数据：用户把自己的文档拖进来。

## 带练步骤（一步一句，做完回报再走下一步）
1. 告诉用户这个项目会得到什么（1 句）。问他：**先用我们的样例长文档试一遍看效果，还是直接总结你自己的文档？**（AskUserQuestion）
2. 若选样例：直接读 `assets/样例数据/长文档-季度经营复盘会议纪要.md`。
3. 若选真实文档：判断格式 —— 是 .docx/.xlsx 就先用 pandoc 或 textutil 转成文本，再读；txt/md/PDF 直接读。
4. 读全文 → 提炼：一句话结论 + 关键决议（带负责人/截止时间）+ 风险 + 行动建议。
5. 抽出待办清单。
6. 输出两份文件：摘要 md（+docx）、待办 md（+docx）。文件名带日期。回报路径。

## 成功标准
30 秒能扫完的摘要，比读原文快得多；且决议带负责人和截止时间。

## 防坑护栏（必须遵守）
- ① Word/Excel **不能直接 Read**（会报英文二进制错），必须先转文本——这是新手最容易卡死的第一步。
- ② PDF 能直读（文字版）；扫描版 PDF 是图片，需 OCR 另说。
- ③ 决议截止时间**照搬原文口径**，原文模糊则摘要也只能模糊（这是源数据问题，不是 Agent 漏掉）。

## 教学闭环（做完这样讲）
- "刚才你只说了一句：『把这份文档总结成摘要 + 待办』。"
- "Agent 自动完成了：读完整篇 → 提炼一句话结论 + 决议 + 风险 → 抽出待办清单。"
- "这件事原本要：人工读 2000 字纪要 + 提炼，每份 10–15 分钟。"
- "以后你自己只要说这一句：『把这份文档总结成摘要 + 待办，Word 先转文本』。"
- "还能这样玩：① 一次丢一整个文件夹批量总结；② 几十万字超长 PDF 一次吞（本模型 100 万 token，约几百页）。"

## Claude Code vs Codex
- Claude Code（Opus）：上下文 100 万 token，超长文档一次吞得下。
- Codex：默认窗口较小，超长文档可能要分段处理。

## 进阶（问用户要不要）
- 多份文档合并，做出跨期趋势对比。
