# 反馈 bug 给作者（用户同意才发，只发非隐私信息）

> 触发：用户说"反馈/报告bug/发给作者/提个建议"，或教练修完一个报错后主动问"要不要把这个问题反馈给作者帮助改进"。

## 反馈通道（webhook）
作者的飞书反馈机器人 webhook：

```
FEEDBACK_WEBHOOK = <<待作者填入飞书自定义机器人webhook，未填则视为未开通>>
```

- 如果上面还是 `<<...>>` 占位（作者没填）：**不要假装能发**。如实告诉用户"作者还没开通自动反馈通道，你可以把这张截图直接发给作者本人"。结束。
- 如果是真实 URL（以 `https://open.feishu.cn/open-apis/bot/` 或 `https://www.feishu.cn/flow/api/trigger-webhook/` 开头）：按下面流程发。

## 流程（一步步）
1. **先征得同意**（必须）：问用户——"要不要把这个问题**匿名**发给作者帮助改进？我只会发：报错内容、哪个项目/哪一步、你的系统类型；**不会发你的任何数据、文件内容或个人信息**。"用户同意才发。
2. **整理反馈内容**（严格只含下列，逐项自查无隐私）：
   - 项目名 + 卡在哪一步
   - 报错信息（命令报错文本，或用户截图里读到的报错；**剔除任何路径里的用户名、token、邮箱、文件内容**）
   - 操作系统（mac/windows/linux）+ skill 版本（git 最近提交或 README 标注）
   - 一句话复现：用户做了什么、期望什么、实际什么
3. **发送**（飞书自定义机器人消息格式，用 curl；如有代理记得 `--noproxy '*'` 或先 unset 代理，见 [[03-飞书推送]] 代理坑）：
   ```bash
   curl -s --noproxy '*' -X POST "<FEEDBACK_WEBHOOK>" \
     -H 'Content-Type: application/json' \
     -d '{"msg_type":"text","content":{"text":"【agent-onboarding bug反馈】\n项目：XXX / 第X步\n系统：macOS\n版本：<commit/版本>\n报错：<清理后的报错>\n复现：<一句话>"}}'
   ```
   - 若机器人设了"关键词"安全校验，文本里必须含该关键词（作者会在分发说明里写明，默认带上"bug反馈"四个字即可）。
4. **回执**：发成功就告诉用户"已匿名反馈给作者，谢谢你帮忙改进 🙏"；失败就说"没发出去（可能作者通道临时不可用），你可以把截图直接发作者"，并把整理好的反馈文本给用户让他自行转发。

## 铁律
- **没同意不发**；**只发上面列的非隐私字段**；用户的真实数据（聊天记录、评论、邮件、财务数字、文件内容）**一个字都不发**。
- 不把 webhook 原始地址念给用户。
